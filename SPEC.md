# Kennel package format, version 1

This document defines the files of a Kennel registry and of an installed package. Bozzard's
`bozzard-project kennel check` is the authoritative validator. The JSON Schemas in
`schema/` help editors and follow the same field names.

## Registry

A registry is a folder, or an HTTPS base URL, that contains:

| Path | Contents |
| --- | --- |
| `index.json` | Generated by `kennel index`. Never edit it by hand. |
| `schema/pkg.schema.json`, `schema/index.schema.json` | Generated copies of the engine's schemas. |
| `packages/<name>/<name>.pkg.json` | One manifest per package. |
| `packages/<name>/…` | The package's files, except bins that have a `source`. |

`packages/` holds only package folders. Each folder name must equal its package `name`.

At any given commit, a package folder holds a single version. Earlier versions remain in
git history and are tagged `<name>-v<version>`. A raw-file URL pinned to a commit or tag is
a registry in its own right.

### `index.json`

```json
{
  "$schema": "schema/index.schema.json",
  "kennel": 1,
  "packages": {
    "steam": {
      "version": "1.0.0",
      "title": "Steam",
      "summary": "…",
      "category": "integration",
      "tags": ["steam", "multiplayer"],
      "manifest": "packages/steam/steam.pkg.json",
      "sha256": "<SHA-256 of the manifest file's bytes>"
    }
  }
}
```

`manifest` is always `packages/<name>/<name>.pkg.json`. Entries are sorted by name. The
index can list at most 4,096 packages.

## Manifest: `<name>.pkg.json`

Unknown fields are errors. Optional fields may be omitted.

| Field | Required | Rules |
| --- | --- | --- |
| `$schema` | no | Ignored. Conventionally `../../schema/pkg.schema.json`. |
| `kennel` | yes | `1`. |
| `name` | yes | 1–64 characters from `a-z`, `0-9` and `-`. Can't start or end with `-`. Must equal the folder name. |
| `version` | yes | A [semver](https://semver.org) version. Bump it whenever any file of the package changes. |
| `title` | yes | 1–80 bytes, no control characters. |
| `summary` | yes | 1–200 bytes, no control characters. |
| `category` | yes | `integration`, `scripts`, `art`, `audio`, `template` or `tool`. |
| `tags` | no | At most 8 unique tags, each 1–32 characters from `a-z`, `0-9` and `-`. |
| `authors` | yes | 1–16 entries, each 1–120 bytes. |
| `license` | yes | An SPDX expression covering the files the package writes itself. |
| `repository` | no | An `https://` URL. |
| `engine` | yes | See [Engine](#engine). |
| `dependencies` | no | `{ "<name>": "<semver requirement>" }`, at most 32. A package can't depend on itself. |
| `build_env` | no | `{ "<VARIABLE>": "<folder>" }`, at most 8. Variable names use `A-Z`, `0-9` and `_`, and can't start with a digit. Each folder is relative to the installation and must contain at least one bin. |
| `bins`, `scripts`, `assets`, `files` | no | Payload. See [Payload](#payload). |

### Engine

| Field | Rules |
| --- | --- |
| `bozzard` | A semver requirement on the engine version, for example `">=0.1.0"`. |
| `script_api` | The lowest native script API version the package's scripts need. Defaults to 0. |
| `features` | The Cargo features the engine build must enable, at most 16. They are advisory: install prints them. |

### Payload

Every payload entry has these fields:

- `path`: a portable relative path. Rules:
  - `/` separators, at most 512 bytes, ASCII only;
  - no empty, `.` or `..` segments;
  - no `\` or `:`;
  - no `<>"|?*` or control characters;
  - no segment that ends in a space or a dot;
  - no Windows device names.
- `bytes`: the file's size, at most 256 MiB.
- `sha256`: the file's SHA-256, as 64 lowercase hex characters.

Across all four sections, paths must also:

- be unique after ASCII case folding;
- never name a file that is also another file's parent folder;
- never use the manifest's own file name.

A package holds at most 1,024 files.

Each section adds fields:

| Section | Extra fields | Rules |
| --- | --- | --- |
| `bins` | `targets`, optional `license`, optional `source` | `targets` lists 1–8 unique `<os>-<arch>` names, using Rust's `std::env::consts` spelling, for example `linux-x86_64`, `linux-aarch64`, `macos-x86_64`, `macos-aarch64` or `windows-x86_64`. One file can serve several targets. |
| `scripts` | `id` | Rhai sources ending in `.rhai` or `.rs`, at most 1 MiB each. |
| `assets` | `id`, `kind` | Typed scene assets. `kind` is one of `material`, `compute_shader`, `audio`, `prefab`, `image`, `mesh` or `font`. Scripts belong under `scripts`. |
| `files` | none | Documentation, notices, templates. |

Script and asset `id`s are unique, and each starts with `<name>/` followed by `/`-separated
segments of `A-Z a-z 0-9 _ -`, for example `steam/player`. They are the scene catalog IDs a
project should use. That makes `import "<id>"` between a package's scripts (and those of its
dependencies) resolve once a scene lists them.

### Upstream sources

A bin with a `source` is downloaded instead of stored in the registry. Its folder must not
contain a copy.

```json
"source": {
  "url": "https://static.crates.io/crates/steamworks-sys/steamworks-sys-0.13.0.crate",
  "sha256": "<SHA-256 of the download>",
  "archive": "tar.gz",
  "member": "steamworks-sys-0.13.0/lib/steam/redistributable_bin/linux64/libsteam_api.so"
}
```

- `url` must use HTTPS. Plain HTTP works only on loopback, for tests.
- With `archive` (`tar.gz` is the only format in version 1), `member` names a regular file
  inside the archive. That file must appear exactly once.
- Without `archive` and `member`, the download is the file itself, so `source.sha256` must
  equal the bin's `sha256`.

The installer and `kennel check --fetch` treat each source like this:

1. Download the source at most 512 MiB, or reuse it from the cache, and verify its SHA-256.
2. Stream out only the named member, reading at most 1 GiB of unpacked data.
3. Verify the member's `bytes` and `sha256`.

Paths inside an archive are only compared. They are never used to create files.

## Registry check

`kennel check <registry> [--fetch]` requires all of the following:

1. Every manifest is valid and matches its folder name.
2. Each package folder contains exactly the manifest plus its listed non-`source` files,
   with matching sizes and hashes. There are no links and no extra files.
3. Every dependency exists in the registry and satisfies its requirement.
4. The scripts compile as one catalog together with their dependencies' scripts. This
   checks syntax, imports and the argument counts of engine hooks.
5. The assets load through the engine's asset store.
6. `index.json` and `schema/*` are byte-identical to what `kennel index` would write.
7. With `--fetch`, every upstream file downloads and verifies.

## Installation

`kennel install <name> <project>` works in this order:

1. It installs dependencies first and detects cycles.
2. It checks each package's `engine.bozzard` and `engine.script_api` against the running
   engine.
3. It writes the files into a staging folder, then publishes them atomically as
   `<project>/kennel/<name>/`, with an unchanged copy of `<name>.pkg.json`.
4. It writes `<project>/kennel.lock.json`:

```json
{
  "kennel": 1,
  "packages": {
    "steam": {
      "version": "1.0.0",
      "registry": "https://raw.githubusercontent.com/Bozzard-Engine/bozzard-plugin-library/main",
      "manifest_sha256": "<SHA-256 of the installed manifest copy>",
      "targets": ["linux-x86_64"]
    }
  }
}
```

By default, only the host target's bins are installed. `--all-targets` installs every
target's bins. An installation is intact when two things hold:

- its manifest copy hashes to `manifest_sha256`;
- its folder holds exactly that manifest's files for the locked targets, with matching
  sizes and hashes.

`install` won't replace an installation that isn't intact unless `--force` is given, and
neither will `remove`. `remove` also refuses while another installed package depends on
the package. `build_env` entries are reported as absolute paths inside the installation.

## Compatibility

A new manifest field or rule that older engines would reject requires a new `kennel`
version. Engines refuse versions they don't know.
